# v1.3 总方案（所有 worker 必读）

日期：2026-09-22。主控：Fable（只派活、不写代码）。执行：Opus（Kotlin 核心）、Sonnet（文档 / 发布）、Grok（评审）。

## 目标

1. **API 自定义**：判断 / 回复 / 视觉三路接口的地址、密钥、模型全部可配，带预设与各自连通测试。
2. **知识库 + 关联上下文**：用户可维护本地知识库（笔记 + 联系人档案）；每次分析自动带上对该联系人的历史记录与相关知识，回复与知识库一致；联系人跨 App 关联（别名）。
3. **OCR 采集**：读不到控件树的 App（飞书正文、任意未适配 App）走截屏 + OCR；已适配 App 树读空时 OCR 兜底。
4. 版本 1.3，release 包，README 更新。

## 顺序与依赖

A（API）→ D（知识库 / 上下文）→ B（OCR）→ C（文档 / 发布）。每阶段一个 Opus agent 顺序做，构建通过再进下一阶段。**同一时间只有一个 agent 改代码**（gradle 与文件都会冲突）。

## 硬约束（照抄 CLAUDE.md，再加三条）

- 绝不自动发送、不碰钱、密钥不落盘不进日志不进 git、UTF-8、禁 git commit/push。
- **所有用户数据（知识库、联系人、历史记录）只存 App 私有目录**，提供"清空"按钮；聊天正文不进 logcat。
- **旧配置必须自动迁移**：升级后原来的 OpenRouter 密钥、回复模型、关系描述、白名单、透明度、开关全部保留可用。
- 传统 View + XML，不引 Compose；不引 Room（用 JSON 文件 + 内存缓存即可）；ML Kit 只在 B 阶段引。

## 公共契约（命名定死，跨阶段复用）

### Prefs 新字段（A 阶段建，后续阶段只读）

```
// 判断接口（Jev）
judgeProvider: String   // "openrouter" | "typesafe" | "custom"，默认 openrouter
judgeBaseUrl: String    // openrouter 默认 https://openrouter.ai/api ；typesafe 默认 https://api.typesafe.ai
judgeKey: String        // 迁移：老 openRouterKey → judgeKey
judgeModel: String      // openrouter 默认 typesafe/jev-1.13 ；typesafe 默认 jev-latest
// 回复接口（任何 OpenAI 兼容 chat completions）
replyBaseUrl: String    // 默认 https://openrouter.ai/api/v1 ；填到 /v1 为止，客户端自己拼 /chat/completions
replyKey: String        // 留空 = 用 judgeKey
replyModel: String      // 老字段沿用，默认 deepseek/deepseek-chat-v3.1
// 视觉接口（OCR 用，OpenAI 兼容，支持 image_url）
visionBaseUrl: String   // 默认同 replyBaseUrl
visionKey: String       // 留空 = 用 replyKey → judgeKey
visionModel: String     // 默认 qwen/qwen2.5-vl-72b-instruct（OpenRouter 区域可用；用户可改）
// 上下文（D 阶段）
contextEnabled: Boolean       // 记录历史并注入，默认 true
contextHistoryCount: Int      // 注入最近多少条历史，默认 30
autoSummary: Boolean          // 联系人自动摘要，默认 true
// OCR（B 阶段）
ocrEngine: String             // "mlkit" | "vision"，默认 mlkit
ocrForUnknownApps: Boolean    // 未适配 App 走通用 OCR，默认 true
ocrFallback: Boolean          // 已适配 App 树读空时 OCR 兜底，默认 true
ocrAutoAnalyze: Boolean       // OCR 模式自动分析，默认 false（手动点）
```

判断接口的请求路径：openrouter → `{judgeBaseUrl}/alpha/decisions`；typesafe → `{judgeBaseUrl}/v1/systemone`；custom → 用户填完整 URL 到 `judgeBaseUrl`，原样 POST。请求体三者相同 `{model, state, questions}`。

### 模型客户端拆分（A 阶段）

```
jev/JudgeClient.kt   // 只管 Jev：judge(snapshot, context) / rank(candidates)
jev/ReplyClient.kt   // 只管生成：draft(snapshot, context) → 3 条；summarize(text) → 摘要（D 用）
jev/VisionClient.kt  // 只管视觉：extractDialog(bitmap) / ocrLines(bitmap)（B 用，A 阶段只建壳）
jev/HttpJson.kt      // 共用的 POST JSON + 退避 + 错误归类（把现在 JevClient 里的 postJson 抽出来）
```
旧 `JevClient` 删除或改成薄门面，调用方（ChatCaptureService、SettingsActivity 连通测试）改用新类。错误信息必须带"哪一路 + HTTP 状态码 + 前 120 字响应"。

### 知识库 / 上下文数据模型（D 阶段）

存放：`context.filesDir/kb/notes.json`、`kb/contacts.json`、`kb/logs/<contactId>.json`。

```
Note(id, title, content, tags: List<String>, alwaysOn: Boolean, enabled: Boolean, updatedAt)
Contact(id, name, aliases: List<String>, apps: List<String>, relationship: String, notes: String,
        autoSummary: String, summaryAtCount: Int, updatedAt)
LogEntry(side, text, ts, app)          // 每联系人一个文件，最多保留 300 条，按 (side,text) 去重追加
ChatContext(contact: Contact?, history: List<LogEntry>, notes: List<Note>, budgetChars = 1500)
```

匹配规则：会话标题 == contact.name 或 ∈ aliases（忽略大小写与首尾空白）→ 命中；未命中且 contextEnabled → 以标题自动建 Contact（apps 记录来源包名）。笔记检索：alwaysOn 的全带；其余按「标题 + 最近 6 条消息」与笔记「title + tags + content」的中文字符二元组重合度打分，取前 5，且总字符不超 budget。

注入方式：Jev 的 state 加 `background` 字段（关系 + 联系人备注 + 自动摘要 + 命中笔记）与 `history`（历史消息，去掉屏幕上已有的）；回复提示词加「以下是关于我和对方的背景与知识库，回复必须与之一致，不要编造知识库没有的事实」。

### OCR 分层（B 阶段）

```
capture/ocr/ScreenCapture.kt   // AccessibilityService.takeScreenshot 封装：限频 ≥1s、失败原因枚举、Bitmap 回调
capture/ocr/OcrEngine.kt       // interface: recognize(bitmap, region): List<OcrLine(text, bounds)>
capture/ocr/MlKitOcr.kt        // com.google.mlkit:text-recognition-chinese（bundled）
capture/ocr/VisionOcr.kt       // 走 VisionClient，可返回结构化对话
capture/ocr/BubbleGrouper.kt   // OCR 行 → 气泡：按行距、左右对齐分组；side 按气泡贴左/贴右
capture/GenericOcrAdapter.kt   // 任意包名：裁掉顶栏（有标题的）与输入区（有 EditText 的），中间区域 OCR
capture/FeishuAdapter.kt 改造 // 树拿 bubble_content_container 矩形 + 已读容器判 me；每个矩形 OCR 正文
```
无障碍配置加 `android:canTakeScreenshot="true"`。截屏失败（FLAG_SECURE、间隔太短、系统限制）要在悬浮窗上给一句人话。

# 修订（2026-09-22 00:30，Grok 4.7 评审后；与上文冲突时以本节为准）

## A 阶段补充
- 迁移只做一次：写 `prefs_migrated_v13=true` 标记后不再读 `openrouter_key`；`judgeKey` 被用户清空不得复活。旧存储名一个不改。
- `replyKey` / `visionKey` 保持空 = 继承；保存时**不要**把空的关系描述替换成默认值。
- 预设按钮必须原子地同时写 base URL 与模型名；视觉接口未单独配置时固定 OpenRouter 视觉模型，**不跟随回复接口**。
- 视觉请求：图片用 `data:image/jpeg;base64,`（`Base64.NO_WRAP`），通义 compatible-mode 图片 part 放文本前；DeepSeek 官方不支持 image_url，测试时要提示"该接口不支持视觉"。
- Jev state 新增 `background` 字段的兼容性：先用一条 fixture 打现网确认 `alpha/decisions` 是忽略还是 400；题目英文 instructions 加一句 "facts in background are given context, not off-topic"，排序题同理。

## D 阶段（知识库 / 上下文）收窄
- **默认关闭落盘**：`contextEnabled` 默认 false；设置里开关文案"记录聊天历史（只存本机，用于关联上下文）"，主页就绪卡提示可开启。README 同步说明。
- **不自动建档、不自动摘要**：联系人只由用户手建（或在悬浮窗菜单里"把当前会话存为联系人"一键建）；`autoSummary` 推迟，`ReplyClient.summarize` 留着不接。
- **检索只做两层**：alwaysOn 笔记全带（单独占预算，不截断）；其余笔记按「标签 / 标题 ∈ 会话标题或最近 6 条消息」的包含匹配，命中才带，最多 5 条；不做二元组打分。
- 名称规范化：去首尾空白、零宽字符、群名尾部 `(数字)`、大小写不敏感后再匹配 name / aliases。
- 历史去重：只删与当屏消息 (side,text) 完全相同、且长度 ≥ 4 的副本。
- 存储：JSON 文件单写者（`synchronized` + 原子写临时文件再 rename）；"清空"只删 `filesDir/kb`，不动密钥与白名单。
- 悬浮窗显示一行"知识库 N 条 · 历史 M 条"。

## B 阶段（OCR）收窄
- **1.3 只做两件事**：① 飞书：树上 `bubble_content_container` 矩形 + 已读容器判 me，对每个矩形做 ML Kit OCR（OCR 结果里剥掉"已读"）；② 通用入口：悬浮窗菜单"截屏识别一次"，对任意 App 手动截一次整屏 OCR 并分析，**不自动、不按左右判 me/other（全部记为 other 并在面板标注"未分边"）**。视觉模型 OCR 不进采集主路径。
- 适配器契约拆分：`extract` 返回 `null` = 不在聊天窗；返回 `ChatSnapshot(messages 为空)` = 在聊天窗但树里没正文。服务只对后者走 OCR 兜底，且失败退避（1s → 2s → 4s，上限 30s），绝不每秒连射。
- 截屏实现：优先 API 34 `takeScreenshotOfWindow`，回退 `takeScreenshot(DEFAULT_DISPLAY)`；截前隐藏悬浮窗、截后恢复；回调里 `copy(ARGB_8888)` 后立刻 `close()` HardwareBuffer；矩形在回调里重读并按 bitmap/屏幕比例缩放；全局限频 ≥ 1000ms；错误码 1/2/3/4/6 各给一句人话。
- 无障碍 XML 加 `canTakeScreenshot="true"` 后**必须关掉再开无障碍**才生效（写进验收）。无障碍服务在 HyperOS 上可能被单独拒绝截屏——B 开工第一步先真机打一次 `takeScreenshot` 看 errorCode，被拒则另起一个截屏专用服务。
- ML Kit：锁 `com.google.mlkit:text-recognition-chinese`（bundled，非 play-services 版），`ndk.abiFilters = arm64-v8a`，选支持 16KB 页对齐的版本；包体增量与"这台无 GMS 手机识别一次"写进验收。
- 手机今晚不在，B 的真机验证放到早上；代码可以先写。

## C 阶段
- versionCode 升、versionName 1.3，`targetSdk` 保持 35 不要抬到 36；记录 release 包体积。
